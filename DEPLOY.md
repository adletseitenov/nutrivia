# Nutrivia на Railway — за 10 минут

Один сервис: веб-версия приложения и API на одном адресе. Сборка — по `Dockerfile` в корне, настройки — `railway.json`.

## 1. Проект

1. railway.com → **New Project → Deploy from GitHub repo** → `adletseitenov/nutrivia` (ветка `main`).
2. Railway сам найдёт `Dockerfile` и `railway.json`. Первая сборка ~5–7 минут (ставит зависимости веб-версии).

## 2. Том для базы и фото

Сервис → **Settings → Volumes → Add Volume**, путь монтирования: **`/data`**.
Без тома база стирается при каждом перезапуске.

## 3. Переменные (Service → Variables → Raw Editor)

```
AUTH_SECRET=<длинная случайная строка>
ADMIN_TOKEN=<длинная случайная строка, вход в /admin>
SMS_PROVIDER=manual
VISION_PROVIDER=openrouter
OPENROUTER_API_KEY=<ключ OpenRouter>
AI_DAILY_USD=3
DEMO_SEED=1
DEMO_CLIENT=<номер Алана, +77…>
```

Случайную строку можно получить так: `openssl rand -hex 32`.

- `SMS_PROVIDER=manual` — SMS не шлём, код входа выдаёт админка `/admin` («Код входа участнику»).
- `AI_DAILY_USD` — потолок трат на ИИ в сутки. Исчерпан — фото всё равно принимаются, блюда человек выбирает из базы.
- `DEMO_CLIENT` — номер, на который создаётся демо-клиент с неделей (номер Алана). Держим только здесь: репозиторий открытый.
- `DEMO_SEED=1` — при первом запуске создаст демо-аккаунты (клиент с неделей, тренер, оператор). Повторно не пересоздаёт.
- `DEMO_SEED=reset` — пересоздаёт демо-аккаунты при каждом запуске, неделя заканчивается **сегодня**. Нужно в день показа (см. ниже). После показа — удалить переменную.
- Порт Railway задаёт сам (`PORT`), трогать не нужно.

## 3a. Уведомления в Telegram (по желанию, 3 минуты)

В PWA на iPhone нет пушей — их заменяет наш Telegram-бот. Клиент в профиле нажимает «Уведомления в Telegram» →
открывается бот → «Старт» → готово.

1. В Telegram написать **@BotFather** → `/newbot` → имя `Nutrivia` → username, например `nutrivia_kz_bot` → он пришлёт токен.
2. Railway → Variables → `BOT_TOKEN=<токен>`. Сервис перезапустится сам.
3. Проверка: в логах строка «Telegram-бот @… подключён», в профиле клиента появилась строка «Уведомления в Telegram».

Что приходит клиенту: «✅ Тренер проверил разбор» сразу после «Отправить»; в 11:00 — про завтрак, если фото ещё нет;
в 16:00 — «Совет на вечер» с блюдами из базы; в 20:00 — сколько фото осталось, чтобы день засчитался в серию.
Каждое — не чаще раза в день. Кнопка «Открыть Nutrivia» в сообщениях ведёт на адрес Railway (`RAILWAY_PUBLIC_DOMAIN`,
или задать свой `PUBLIC_URL`).

- Один токен — один запущенный бот. Если этот же бот уже работает где-то ещё, Telegram будет отдавать сообщения
  то туда, то сюда — тот запуск остановить.
- Тот же бот без ссылки из приложения работает как бот-консьерж фазы 0 (фото в личку → разбор). Фото там тоже
  тратят ИИ — в пределах `AI_DAILY_USD`.
- `SOLO_REVIEW_CHAT_ID=<id группы>` (необязательно) — разборы из приложения дублируются карточкой в Telegram-группу
  проверки; id группы покажет команда `/chat_id`, если добавить бота в группу.

## 4. Адрес

**Settings → Networking → Generate Domain** → получится `https://….up.railway.app`.
Проверка: `https://…/health` отвечает `{"ok": true}`, на `https://…/` открывается приложение.

## 5. На iPhone

1. Safari → адрес → «Поделиться» → **«На экран Домой»**. Иконка — голубика, приложение открывается без строки адреса.
2. **Входить уже в приложении с экрана «Домой»**, не в Safari: у них раздельная память, а код из админки одноразовый.
   Вошли в Safari — для иконки понадобится новый код.
3. Вход: номер → код из `https://…/admin` («Код входа участнику»).

## В день показа (после 13:30, за 1–2 часа до показа)

Демо-неделя считается от дня, когда аккаунты создались. Если их создали раньше, сегодня у клиента будет пусто
и не будет «Совета на вечер». Сегодняшние завтрак (8:35) и обед (13:15) записываются, только если это время
уже прошло, — поэтому сбрасывать после 13:30, тогда серия 7 дней и стадия 3. Порядок:

1. Variables → `DEMO_SEED=reset` → Railway сам перезапустит сервис (~1 мин). Неделя теперь заканчивается сегодня:
   завтрак и обед записаны, вечер пустой.
2. Старые входы на демо-номерах сброшены — выдать новые коды в `/admin` и войти на iPhone (шаг 5.2).
3. После этого вернуть `DEMO_SEED=1`, иначе любой перезапуск снова сотрёт то, что вы добавили на показе.

## Демо-аккаунты (`DEMO_SEED=1`)

| Роль | Номер | Что внутри |
|---|---|---|
| Клиент | `DEMO_CLIENT`, без неё +7 700 000 00 01 | неделя проверенных разборов, вес, серия 7 дней, посты в ленте; вечер пустой — видно «Совет на вечер» |
| Тренер | +7 700 000 00 02 | 3 ученика, один разбор ждёт проверки, итог недели |
| Оператор | +7 700 000 00 03 | кабинет оператора |

Пересоздать с нуля — `DEMO_SEED=reset` (раздел «В день показа»).

## Если что-то не так

- **Сборка упала** — Deployments → лог сборки.
- **Фото не распознаются** — проверить `OPENROUTER_API_KEY` и баланс OpenRouter; в `/admin` видны ошибки ИИ. Приложение при этом не ломается: предлагает выбрать блюда вручную.
- **После перезапуска всё пропало** — не подключён том `/data` (шаг 2) или осталась `DEMO_SEED=reset`.
- **Нет строки «Уведомления в Telegram»** — не задан `BOT_TOKEN` или Telegram его не принял (в логах «BOT_TOKEN …»).
- **«Слишком много запросов» при входе** — лимит 60 запросов входа за 10 минут с одного адреса (общий Wi-Fi в зале). Подождать пару минут или войти через мобильный интернет.

# Nutrivia — concierge-бот фазы 0

Telegram-бот для двухнедельной проверки гипотезы (раздел 1a плана). Клиент присылает фото еды. Модель предлагает черновик: блюда и граммы. Человек в закрытой группе проверяет и нажимает «Отправить». Калории и БЖУ считает код по базе блюд. Модель их не считает.

## Как устроено

| Файл | Что делает |
|---|---|
| `nutrivia/engine.py` | Расчёт `per_100g × grams / 100` и местные меры («1½ × пиала (≈450 г)») |
| `nutrivia/matcher.py` | Поиск блюда: точное имя → синоним → fuzzy (rapidfuzz). Разбор правок «плов 350» |
| `nutrivia/vision.py` | `ClaudeVision` на `claude-opus-5-5`: JSON-схема, `fallbacks="default"`, обработка отказа и ошибок, стоимость. `FakeVision` для офлайна |
| `nutrivia/service.py` | Вся логика без Telegram: онбординг, фото → черновик, проверка, ответ, правки, совет, итог, оффер, `/delete` |
| `nutrivia/bot.py` | aiogram 3: личка клиента, группы проверки, расписание (19:00 совет, вс 20:00 итог, 12:00 оффер) |
| `nutrivia/advice.py` | Совет и недельный итог по правилам и шаблонам, без LLM |
| `nutrivia/texts.py` | Все тексты RU/KK |
| `nutrivia/metrics.py` | Метрики гейта из таблицы `events` |
| `data/dishes.csv` | **Черновая** база из 40 блюд (значения на 100 г). `verified=0`: нутрициолог должен сверить её до запуска |

## Запуск

1. Создайте бота у @BotFather и отключите ему privacy mode (`/setprivacy` → Disable). Иначе бот не увидит ответы в группах проверки.
2. Создайте закрытую группу для «одиночек» и добавьте туда бота. Узнайте id группы командой `/chat_id` в ней.
3. Скопируйте `.env.example` в `.env` и заполните: `BOT_TOKEN`, `SOLO_REVIEW_CHAT_ID`, `ADMIN_IDS`, `ANTHROPIC_API_KEY`, `KASPI_PAY_URL`.
4. Запустите бота:

```bash
.venv/bin/python -m nutrivia.bot
```

Через Docker (БД и фото на томе `/data`). Образ по умолчанию запускает API для приложения, бот — той же картинкой:

```bash
docker build -t nutrivia . && docker run -d --env-file .env -p 8000:8000 -v $(pwd)/data:/data nutrivia
docker run -d --env-file .env -v $(pwd)/data:/data nutrivia python -m nutrivia.bot
```

Бот работает через long polling: для фазы 0 так проще, чем webhook, и не нужен домен.

## Пилот с Мака (5–10 человек, Expo Go)

Сервер и приложение работают на Маке, наружу — через бесплатные туннели Cloudflare (`cloudflared`, без аккаунта).

1. В `.env` (уже создан, база `data/pilot.db`) впишите ключи и перезапустите:
   - `VISION_PROVIDER=openrouter` и `OPENROUTER_API_KEY` — настоящее распознавание. Модель по умолчанию `anthropic/claude-sonnet-5.5`, дешевле — `VISION_MODEL=google/gemini-3.8-flash`.
   - Вход: сейчас `SMS_PROVIDER=manual` — SMS не шлём, коды выдаёте сами (шаг 4). Когда будет Mobizon: `SMS_PROVIDER=mobizon` и `MOBIZON_API_KEY`.
2. Запуск одной командой: `scripts/pilot.sh`. Он поднимает API, два туннеля и Metro и печатает ссылку `exps://…` (она же в `data/pilot-logs/link.txt`). Пока скрипт работает, Мак не засыпает.
3. Нутрициолог (Алан) регистрируется первым как «нутрициолог» и берёт код в кабинете. Этот код впишите в `DEFAULT_INVITE_CODE` и перезапустите: тогда клиенты без кода тоже попадут к нему, и все разборы видны в приложении, без Telegram.
4. Каждому участнику (и Алану): `.venv/bin/python -m scripts.pilot_code +7707…` — печатает готовое сообщение для WhatsApp: ссылка, инструкция про **Expo Go** и код входа. Код одноразовый, 7 дней; номер без кода войти не может. Повторный запуск выдаёт новый код (если человек вышел или код не подошёл).
5. Проверка снаружи: `.venv/bin/python -m scripts.smoke_pilot <адрес API> [фото_еды.jpg]`. Создаёт двух тестовых пользователей, проходит фото → проверка → клиент видит и удаляет их.

Ограничения: ссылки меняются при каждом перезапуске скрипта — разошлите новую. Выключенный или спящий Мак — пилот стоит. Демо-сервер (`data/api-demo.db`, порты 8000/8081) не трогается.

## API для мобильного приложения

Сервер `nutrivia/api.py` (FastAPI) работает поверх того же `Service`, той же базы и той же группы проверки, что и бот. Приложение (`../nutrivia-app`) отправляет фото на сервер. Ключ AI хранится только здесь. Разбор делает claude-opus-5-5, калории считает Engine.

```bash
.venv/bin/python -m nutrivia.api           # http://localhost:8000, документация на /docs
VISION_PROVIDER=fake .venv/bin/python -m nutrivia.api   # без ключа, офлайн
```

| Метод | Что делает |
|---|---|
| `POST /v1/auth/sms/start` | `{phone}` → отправить код из SMS (только казахстанские мобильные +7 7XX) |
| `POST /v1/auth/sms/verify` | `{phone, code}` → токен. Для нового номера ещё `consent: true`, `role` (`client` / `trainer` / `nutritionist`), `goal`, `name` (для специалиста), `invite_code` |
| `POST /v1/auth/logout` | Завершить сессию |
| `GET /v1/me`, `PATCH /v1/me` | Профиль, роль, специалист; смена цели |
| `POST /v1/me/coach` | Клиент вводит код тренера или нутрициолога |
| `GET /v1/pro/students` | Специалисту: ученики, их калории за сегодня, серия, непроверенные разборы |
| `GET /v1/pro/queue` | Специалисту: непроверенные разборы учеников, старые сверху |
| `GET /v1/pro/meals/{id}`, `…/photo` | Разбор и фото ученика — только своих учеников |
| `PUT /v1/pro/meals/{id}/items` | Правка порций и замена блюд проверяющим. Оценка модели сохраняется для метрики ошибки граммов |
| `POST /v1/pro/meals/{id}/comment`, `…/send` | Комментарий и «Отправить»: тот же `reviewer_send`, что у кнопки в Telegram |
| `POST /v1/meals` | Фото (multipart `photo`, только jpeg, png или webp до 8 МБ) → черновик разбора. Карточка уходит в группу проверки, если задан `BOT_TOKEN` |
| `GET /v1/meals/{id}` | Статус: `draft` (оценка по фото), `reviewed` (проверено), `not_food`. После проверки: `reviewer` (имя и роль, оператор — «Нутрициолог Nutrivia»), `reviewed_at`, `comment`; у блюд `ai_grams` — оценка модели. Черновик комментария до «Отправить» клиенту не отдаётся |
| `GET /v1/meals/{id}/photo` | Фото — только владельцу |
| `PUT /v1/meals/{id}/items` | Правка порций клиентом; пересчитывает Engine |
| `POST /v1/meals/{id}/confirm` | «Верно» |
| `GET /v1/today` | Итоги дня и ориентиры |
| `GET /v1/progress` | Серия дней и стадия маскота, неделя по дням, число проверенных фото, последний комментарий нутрициолога |
| `GET /v1/dishes?q=` | Поиск блюда по базе |
| `DELETE /v1/users/me` | Удаляет все данные, фото, номер телефона и сессии |

Все запросы, кроме входа и `/v1/dishes`, требуют заголовок `Authorization: Bearer <токен>`.

### Вход по SMS (`nutrivia/auth.py`)

- Код состоит из 4 цифр и живёт 5 минут. На ввод даётся 5 попыток, после этого нужен новый код.
- Повторно отправить код можно не чаще раза в минуту и не больше 5 раз в час на номер.
- В базе хранятся только HMAC-хеш кода (ключ `AUTH_SECRET`) и SHA-256 токена. Сессия живёт 90 дней.
- `SMS_PROVIDER=console` ничего не отправляет и пишет код в лог сервера. Это только для разработки. Настоящего провайдера SMS для Казахстана нужно выбрать тестом на Beeline, Kcell/Activ и Tele2/Altel (план, фаза 0) и подключить в `make_sms()` в `api.py`.
- Пока не сделано: ограничение запросов по IP, защита от массовой рассылки на разные номера.

### Типы аккаунтов

При регистрации выбирается тип: «Для себя», «Тренер» или «Нутрициолог».
- Тренер и нутрициолог получают код приглашения из 6 символов. Клиент вводит его при регистрации или позже в профиле.
- Тренер ведёт не больше 5 учеников (`Service.STUDENT_LIMIT`). У нутрициолога лимита пока нет.
- Специалист видит своих учеников как «Ученик 1, 2…» без имени и телефона: калории за сегодня, серию и число непроверенных разборов.
- Специалист проверяет разборы своих учеников прямо в приложении. Параллельно карточка уходит в Telegram-группу; у специалиста без своей группы — операторам в `SOLO_REVIEW_CHAT_ID`. Кто нажмёт «Отправить» первым, тот и проверил; второй увидит «уже отправлено».
- Разбор с блюдом не из базы отправить нельзя: проверяющий заменяет его блюдом из базы или убирает.
- Пока не сделано: после отправки из приложения карточка в Telegram остаётся с кнопками (кнопка ответит «Уже отправлено»).

Бот и API должны работать с одной базой (`DB_PATH`). Когда нутрициолог нажимает «Отправить» на карточке из приложения, в Telegram ничего не уходит. Приложение само забирает статус «проверено»: раз в 15 секунд оно опрашивает сервер.

### Серия и стадия маскота

Правила задаются в `Service.STAGE_DAYS` и `MIN_PHOTOS_PER_DAY`. Сейчас это черновик, его утверждает фаундер.
- День засчитывается, если в нём 2 и более фото еды.
- Каждый засчитанный день добавляет 1 к серии. Стадия растёт на порогах 3, 7, 14 и 30 дней подряд.
- Пропущенный день обнуляет серию, а маскот опускается на одну стадию, но не ниже первой.
- Пока сегодняшний день не закончился, нехватка фото серию не обрывает.

## Подключение нутрициолога

Для каждого нутрициолога своя закрытая группа. В ней админ пишет:

```
/add_coach aigul Айгуль
```

Бот ответит ссылкой `t.me/<бот>?start=c_aigul` для клиентов этого нутрициолога. Для «одиночек» ссылка `t.me/<бот>?start=solo`.

**Если клиенты в WhatsApp.** Нутрициолог шлёт фото клиента в свою группу с подписью `wa Айгерим`. Бот сделает черновик, а после «Отправить» выдаст текст, который нужно скопировать клиенту. Время проверки при этом тоже замеряется.

## Работа в группе проверки

- Карточка: фото, блюда, граммы, уверенность модели, КБЖУ. Блюдо, которого нет в базе, помечено «НЕТ В БАЗЕ».
- **✏️ Править граммы.** Ответьте на карточку строками `плов 350`, `чай 200`. `0` убирает блюдо. Пересчёт идёт по базе.
- **💬 Комментарий.** Текст уйдёт клиенту вместе с разбором.
- **✅ Отправить.** Разбор уходит клиенту. В журнал пишется время от черновика до нажатия.
- `/target 1800` ответом на карточку задаёт клиенту ориентир по калориям.
- `/paid <id> [сумма]` отмечает оплату. Отмечаем только реально полученные деньги.

## Проверка без Telegram и API

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.offline_run
```

Второй скрипт симулирует 2 недели на 12 участниках. Он печатает метрики и пример совета и итога, а CSV складывает в `exports/offline/`.

Один реальный вызов модели (нужен `ANTHROPIC_API_KEY`):

```bash
.venv/bin/python -m scripts.offline_run --photo plov.jpg
```

## Метрики

```bash
.venv/bin/python -m scripts.export_metrics
```

Скрипт создаёт `exports/<дата>/` с файлами:
- `summary.csv`: пороги гейта (удержание D1/D3/D7/D14, время проверки по группам, доля «Верно», оплаты, стоимость AI);
- `gram_error.csv`: ошибка граммов модели против человека по блюдам;
- `missing_dishes.csv`: блюда, которых нет в базе, то есть кандидаты на расширение до 150;
- `events.csv`: сырой журнал событий.

Эти CSV загружаются в Google Sheets.

## Правила (проверяются тестами)

- Ключ AI хранится только на сервере, в `.env`.
- Нутриенты считает только `engine.py`.
- Разбор уходит клиенту только после «Отправить» и всегда с пометкой «оценка по фото».
- Слов «дефицит» и «диагноз» в текстах нет (`tests/test_texts.py`).
- На жалобы на самочувствие бот отвечает «обратитесь к врачу».
- `/delete` удаляет пользователя, его приёмы пищи и фото с диска.
- Каждый вызов AI пишется в `ai_requests` с токенами и стоимостью.
